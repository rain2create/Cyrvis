### ShowUI 观察

1. **单次延迟**：侧车 2.3–3.4s/步（含图片预处理），比 Seed 2.1 Lite 的 2.3–7.5s 稳定且低；模型加载 4.12GB VRAM，未 OOM。
2. **L4 明显更快**：5 轮 vs 11 轮，35.4s vs 104.5s；它直接点击第 3 条结果，不右键、不折腾标签页。
3. **桌面任务不可用**：ShowUI 的 web 动作空间只有 `CLICK/INPUT/SELECT/HOVER/ANSWER/ENTER/SCROLL/SELECT_TEXT/COPY`，没有 `hotkey`、没有 `Ctrl+S`、没有 Alt+Tab；它也不会主动跨应用规划。L1/L5 失败是动作空间和模型能力问题，不是速度问题。
4. **坐标异常**：ShowUI 返回过 `position: [0.21, 45]`（y 不是 0–1）。侧车已把 `1 < v <= 100` 当作百分比（45 → 0.45），大于 100 当作像素；修复后 L4 通过。
5. **连接错误**：App 在约 5 步后出现 `Connection error`，疑似 uvicorn 默认 5s keep-alive 与 App 轮询间隔不匹配；侧车已改为 `timeout_keep_alive=120`，待复测。
6. **定位**：ShowUI 更适合“浏览器内的点击/输入/读取”，不适合“桌面应用 + 快捷键 + 保存”的任务。可行路线是**按任务类型路由**：浏览器任务走 ShowUI，桌面任务走 Seed/UI-TARS；或在侧车上加一层快捷键/保存桥接。

### 观察

1. **Action Batching 是概率性的**：L1 明明可以 `type + Enter` 批量，模型却分成 click → End → type → Enter → Ctrl+S → finished 六轮；L4 第一轮搜索框已聚焦，模型才批量了 `type + Enter`。提示词存在不等于模型每次都会用。
2. **L1 的点击是多余的**：模型先点了 `[60,131]`（Notepad 标签/菜单附近），又按 End，再输入。虽然成功，但多了两轮。任务指令可以更明确“光标已在末尾，不要点击”，但基线保留原指令。
3. **L4 的标签页操作很绕**：右键 → “在新标签页打开”时误开了一个空白新标签，随后切换、返回、重开，最终直接点击第 3 条结果进入详情页。11 轮里有 5 轮在纠正标签页状态；这是状态依赖任务的典型成本。
4. **Token 随历史增长**：L4 的 prompt tokens 从 2076 涨到 7949（5 张历史截图 + 动作历史）。这是“历史截图 5→1”实验的直接依据。
5. **L5 没有批量**：模型读码后点击 Notepad 可见区域切窗、输入、Ctrl+S、finished，四轮干净完成；跨应用任务主要成本在窗口切换和读后记忆，不在按键数量。
6. **R1 是长任务的压力测试**：携程页面卡在目的地下拉/日期选择，模型反复点击、Esc、刷新，刷新后又回到默认“深圳→北京、往返”，27 轮后 300s 超时。期间没有登录/预订/填乘客信息。它暴露的是真实网站的交互状态复杂 + 上下文/token 爆炸，不是 Action Batching 能解决的。
